# Keyboard 可选指导 v8（2026-10-30）

本轮在当前开发代码上移除无匹配回退卡，不回滚历史 Mini v3，不新增规划模型或检索工具，也不改写 `3800520` 及其他冻结实验。`capability_guidance_v8` 是指导策略版本，和历史 Mini v7 的版本名称无关。

## 已实现的边界

- 删除指导库及准入契约中的 `focus.verify`，同时删除无匹配和像素重复检测对该卡的自动选择。重复检测仍保留本地诊断；已有来源支持的具体未完成动作、真实错误仍可进入 Current。
- 找不到适用指导时返回 `groups=[]`、`needed_groups=[]`、`selection_status=no_match`。模型收到空 Keyboard 和其余 View，可自行构建合法原生动作，无须先输出 lookup 或找到一个目录条目。
- 取消无匹配时自动补入广泛目录的行为。能力未冻结或绑定缺少契约仍保留具体缺口，不发送猜测配方；缺口也不禁止模型依据当前界面作出原生决策。
- 非空指导仍按当前阶段、软件对象和冻结能力筛选，一张完整指导组原子准入。保留适用条件、准确参数、必要依赖和检查方法，不用无关的便宜卡替代放不下的当前卡。
- `no_match` 和 `omitted_budget` 分开：前者没有候选，后者有合格候选但预算不足。两者都不强制模型依赖 Keyboard。
- 原生动作不要求与卡中绑定一致。复制卡可以提供 Ctrl+C，模型仍可依据截图使用可见菜单。配方参数匹配不能证明采用建议或业务成功。

保留有具体操作意义的无固定按键指导，例如可见 Export 流程、拖拽起点与终点、已经输入缩放值后的单次确认，以及粘贴后的结果检查。它们有明确动作和适用阶段，不是无匹配兜底。当前库由 43 张卡减少为 42 张；本轮没有拓宽任何按键绑定。

补充包继续受 **3000 UTF-8 bytes** 及实际原生请求余量约束。Current、最新执行、真实错误与来源检查保持；有无匹配均不新增模型调用，不修改官方动作编译、终态严格复核和纠错预算。

冻结配置增加 `usage=optional_reference_not_action_requirement`、`unmatched=empty_keyboard_native_actor_decides`，策略及打包版本一起更新。旧策略不能在新代码上静默恢复；历史实验应继续使用其冻结源码和目录，新实验重新准备计划。

## 当前真实交互顺序

```text
原始任务 + 当前截图 + 原生历史 + 同 episode 的执行 journal
    ↓
确定性重建状态：公开意图有效期、已执行动作、待确认效果、阅读报告
    ↓
确定性检索：适用性过滤 → 当前阶段相关性 → 稳定 ID 排序
    ↓
四个 View 打包：有卡则完整准入，无匹配则 Keyboard 为空
    ↓
注入同一次 CUA actor 请求 → 模型判断并构建原生工具参数
    ↓
来源／协议／终态检查 → 官方编译器 → GUI 执行
    ↓
观察、动作参数、回执和错误写回 journal → 下一轮
```

选卡发生在发送请求前，输入来自任务、既有公开回复和真实日志。它不会读取模型隐藏推理，也不能在本轮模型思考中途即时激活。四个 View 是同一个 actor 的证据投影，不是四个独立 LLM；最终执行器接收经过校验的动作，不接收四份 View 自行推理。

现有 `<key_lookup>guide_name</key_lookup>` 是公开回复里的可选标签，不是可同步返回结果的检索工具。它只影响下一次请求：和该标签一起生成的动作已经形成，不可能使用尚未返回的卡。此时序已用实际请求装配的模拟测试验证。

例如当前请求提供复制卡，模型回复 `Copy selected text. <key_lookup>clipboard.copy_paste</key_lookup>`。完整复制粘贴卡在下一次请求才出现。另一个例子是复制回执已写入 journal，下一轮可选择粘贴阶段卡；回执只证明已派发，不能证明源选区、目标焦点或最终内容正确。若下一步是目录没有覆盖的排版动作，则 Keyboard 为空，模型直接根据截图和任务构建点击或拖拽参数。

## 对五阶段思路的评估

这一划分适合作为同一个 actor 的信息使用顺序，但 Current 必须既参与最初规划，也参与最后的参数定位。

| 环节 | 输入与输出 | 必须保持的边界 |
|---|---|---|
| 路线判断 | 任务目标 + 当前状态 + Lessons 的错误／公开结论 → 当前策略 | 旧模型报告仍是 proposal，不因进入 Lessons 变为事实 |
| 尝试复用 | Attempts 中相近的已执行动作及前后观察 → 可复用步骤或应避开的尝试 | 旧坐标必须在当前截图重新定位；相同工具参数不代表成功 |
| 知识补充 | 明确动作、软件、对象、阶段及缺失的操作知识 → 完整卡或 no_match | 不为路线上的每一步凑卡，不让词法匹配替代目标判断 |
| 执行构建 | 策略 + 可选卡 + 当前真实截图 → 明确工具参数 | 无卡仍可执行；截图变化和工具回执都不自动解决待确认效果 |
| 执行反馈 | 校验后的工具参数 → GUI → 新观察及 journal | Views 在请求前交给 actor，执行器只执行工具命令 |

不应把上述顺序变成强制五次模型调用或每轮必须填满五个标签。当前实现仍是零额外调用的请求前预取，其局限是只能利用上轮已经公开的策略。

若后续需要真正的“本轮先思考策略，再查缺失绑定”，可以增加**可选的** `keyboard.lookup` 工具：actor 只提交简短的操作需求、软件对象、阶段和需要补充的知识；harness 确定性返回卡或 no_match；同一 actor 再结合当前截图构建 GUI 动作。无须公开完整推理过程。该路径通常增加一次 API 往返，应计入预算，并限制相同查询重复、缓存结果、允许无匹配直接行动。检索与 GUI 派发应分开，避免模型在尚未收到卡时同时派发依赖该卡的操作。

本轮没有加入此新工具或改变请求协议。若要验证它，应和请求前预取独立比较，不能把额外思考时间误计为检索收益。

## 指标解释和验证

`packet_delivery_rate` 统计 View 包是否实际送达；`delivered_reference_frame_rate` 统计是否送达非空指导；`no_match_frame_rate` 单独统计没有合格候选的帧。没有候选时，所需配方送达率和流程完整率的分母为零，结果是 `null`，不是 100%。历史缺少新状态字段的日志，不补造 no_match 值。

这些指标只衡量本路由器的候选与投递。仍不能据此证明“当前任务真正需要的卡”已匹配、模型采用建议或减少了决策。需要独立标注或成对在线实验才能判断任务效果。

本轮验证产物在 `outputs/optional-keyboard-v8-20261030/`，包括 600 项离线回归、历史 journal 前缀回放、目录清单及静态检查。测试覆盖空公开回复、任务特定的未覆盖操作、无效 lookup、具体待确认阶段、实际请求与动作编译、checkpoint 策略隔离、极小预算及 flat/linked 同输入一致性。没有真实模型 API 请求或 GUI 派发；历史回放是投递诊断，不是重新执行，也不产生新 benchmark 得分。

主要修改：`keyboard_guidance.py`（允许空候选）、`guidance_eligibility.py` 与 `guidance.json`（删除回退卡）、`guidance_delivery.py`（空 Keyboard 打包）、`mini_taskviews_native.py`（明确可选语义）、`audit_mini_guidance.py`（区分空匹配和实际指导送达）。
