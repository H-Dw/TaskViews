# TaskViews-Mini v0.1.0

首个 release 固定到 **`0a5b6f2a8824008dc3bba01803b1b43369016627`**，保留历史 `mini_keyboard_memory_v3` 实现；不把后续 `main` 的代码回填到这个版本。

## 设计

单一 CUA actor 结合原始任务、当前截图和原生历史执行操作。`current / keyboard / attempts / lessons` 四个确定性 View 提供当前观察、准确按键与 episode 键盘记忆、真实执行尝试和有来源的错误／模型报告。补充上下文共用 3000 UTF-8 bytes 上限，正常操作不新增分析角色模型调用。执行记录保存在 episode journal，沿用共同 native 动作接口和外部 OSWorld 执行／评分底座。

## 效率证据

历史发票／low 对照使用 `qwen3.8-max`、thinking=true、temperature=0、top_p=0.9、最多 40 次决策，两组均冻结于本提交，独立 guest 和空任务记忆：

|指标|LLM baseline|TaskViews-Mini|
|---|---:|---:|
|官方分数|1.0|1.0|
|决策|28|22|
|GUI 命令|27|22|
|API 尝试／完整返回|28／28|22／22|
|输入 tokens|219,061|190,785|
|输出 tokens|7,803|6,095|
|其中推理 tokens|4,723|3,865|
|总 tokens|226,864|196,880|

该记录中决策减少 **21.4%**、总 tokens 减少 **13.2%**。输出已包含推理 tokens。同提交后来的单次原样复现为 1 分、22 决策、6,973 输出 tokens；不保证每次开销相同，也不将单任务结果推广为整体 benchmark 收益。

## 已知缺陷

**该版本虽实现了 CUA 决策效率的提升，但在部分复杂任务上存在结果提交缺陷。** 界面操作完成、工具回执或模型声称成功，不能保证最终文件的来源、内容、路径和提交对象正确。首版未包含后续增加的严格产物来源复核。

同属 v3 核心的后续提交 `4dd4f2b3564dc8a14d7cc18ab14e44435cb16802` 在 VLC 截帧任务中出现将观察截图作为交付图片的问题，官方连续分数为 `0.08199028328542753`。该记录用于说明这类交付风险，**不是 `0a5b6f2` 的直接 VLC 测评结果**。涉及文件生成、导出或提交的复杂任务，仍需核验最终产物及其来源。

## 版本与复现边界

- `v0.1.0` 精确指向上述历史提交，后续 Mini v7、Graph、阶段化复核和能力指导不属于首版。
- 当前 README 位于开发主线，包含新参数；首版应使用其自身代码支持的参数及相应冻结配置。
- 历史已测模型是 SX 接口的 `qwen3.8-max`；开发版的 AutoDL 默认配置不是上述成绩的来源。
- 本 release 提供源码。VM 镜像、模型凭据、任务资源和完整本地原始轨迹不随 release 分发。
- 指标与版本来源见开发主线的[实验总账](https://github.com/H-Dw/TaskViews/blob/main/docs/taskviews-post-v7-experiments-20261029.md)及[README 来源说明](https://github.com/H-Dw/TaskViews/blob/main/docs/readme-provenance.md)。

本项目基于 UI-KOBE，保留 Apache-2.0 许可和上游署名。
