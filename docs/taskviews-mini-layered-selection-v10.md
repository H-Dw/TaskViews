# Keyboard 分层选择 v10（2026-10-30）

本轮基于 `3800520` 的 Graph 开发代码及随后 v8/v9 工作区改动，替换数值评分，不回滚至历史 Mini v3。新冻结身份为 `capability_guidance_v10` / `layered_guidance_v10`，选择契约为 `layered_guidance_selection_v1`。历史冻结源码、计划和结果保持原样。

## 规则顺序

```text
适用性、来源和有效期过滤
→ 当前阶段是否允许
→ 与本轮明确操作需求的匹配程度
→ 软件和对象的适用程度
→ 是否覆盖声明的知识缺口
→ 稳定内容 ID
```

采用命名分支逐层分组。没有总分、权重、数字优先级或把枚举转成数字的排名公式。后一层不能补偿前一层的差异；明确不满足硬性条件的候选退出选择，而不是靠其他优点加分留下。

| 层 | 规则 | 边界 |
|---|---|---|
| 适用性／来源／有效期 | 沿用冻结能力、启用目录、软件对象、动作契约、同 episode 原始来源校验；过期意图和状态排除 | 软件名称与目录启用均不证明窗口或焦点；来源不一致仍在 actor 请求前阻断 |
| 当前阶段 | 先选允许的阶段卡，排除重新开始旧步骤的卡；明确区分当前必要动作、执行后检查和待续步骤 | 已输入缩放值不重新输入；粘贴后转向检查；返回回执不证明业务成功 |
| 当前操作匹配 | 合适的显式引用、覆盖完整当前操作、部分当前操作、执行依赖、宽泛目标支持 | 显式引用仍需先通过准入和阶段检查，不能因点名而越权 |
| 软件／对象 | 已明确的软件范围、匹配的对象类型、通用范围 | GIMP 专用导出卡的选择依据是明确的软件目标；不再使用 `+2` |
| 知识缺口 | 满足已识别的全部要求、满足允许的替代要求、未指定可解析要求 | 不满足明确要求的卡退出；未识别需求不能被写成已覆盖 |
| 稳定 ID | 前述条件相同才按内容 ID 排列 | 目录和候选生成顺序不决定结果 |

当前阶段冲突由命名条件处理，不用 `98 > 95` 决定。仍保留已有的条件顺序：同一当前视图中有效的公开可读性报告可进入直接阅读分支；否则处理待确认缩放，再处理阅读调整链。报告仍是未验证 proposal；待确认状态和原始证据不因选卡而升级为成功。

剪贴板有待粘贴状态时，明确的目标路径输入等当前必要操作可先于粘贴，粘贴仍是候选。没有更直接的公开需求时，待续粘贴优先于一般目标指导。执行粘贴后的检查阶段不再依赖 100 分。

## 不再比较数字的来源处理

原始任务和最近公开意图继续采用原来的有效期和选择边界。最近的意图覆盖更早意图，本轮 `keyboard_lookup` 的公开需求替换历史意图；原始任务冻结能力，不与当前请求加权竞争。

同一张卡经不同来源产生时，合并来源引用和原因，保留实际工作流身份，不再通过“哪一个分数更高”丢弃另一份证据。完整 URL、条件判定和选择解释留在本地审计，模型仍只收到短完整指导及必要事件引用。

## `missing_knowledge` 的实际作用

预取和本轮查询使用同一套分层规则。本轮查询额外将经验证的 `missing_knowledge` 传入选择器，识别常见的按键绑定、操作方法／参数、完整流程以及结果检查需求。仅当前 `intent` 产生操作候选；知识缺口不会启用新软件或扩展冻结能力。

具体行为：

- `Copy selected text` + `Exact copy binding`：直接复制指导。
- 相同 intent + `Complete copy and paste workflow`：补充该操作已声明的后续依赖，选择完整复制粘贴组。确认／粘贴等依赖仍受冻结能力和当前阶段约束。
- `Drag the object` + `Exact keyboard shortcut`：没有已审查的对应绑定时返回 no_match，不把一个无关按键当作答案。
- 相同拖拽 intent + `Procedure and parameters`：可提供有具体起点、终点及检查要求的拖拽指导，即使没有键盘绑定。
- 图像编辑卡包含 Undo，不代表它能回答“图像编辑操作本身的准确按键”；相关性检查区分当前操作和卡内的恢复绑定。
- “按键 **或** 方法”允许一种满足；“按键 **和** 方法”要求两种满足。完整流程依照已声明的 workflow／依赖信息检查，不能只凭非空 `steps` 字段宣布覆盖完整。

无法识别的自由文本需求标记为 `unspecified`，不会据此声称已覆盖。这里的覆盖仅表示满足规则识别出的声明要求，仍不是独立人工标注、模型采用证明或 GUI 成功证明。

## 审计与模型上下文

候选不再含 `score`。每个候选保存命名的 `criteria`、操作／绑定契约、实际覆盖的需求项及来源列表。`selection_explanation` 保存当前阶段、胜出卡、胜出条件以及相对于其他候选的第一个决定层。

未覆盖缺口的候选记入排除审计。若其他候选完整覆盖需求，不将某张被排除的卡误记为全局缺口；所有候选均不能覆盖时，Current 明确记录知识缺口，Keyboard 为空，模型仍可原生决策。

解释和候选元数据不会进入模型操作卡，也不会占用 View 包预算。保留 3000 UTF-8 bytes 上限、关键执行与真实错误优先、一张完整指导组原子准入、flat/linked 按 linked 成本选择同一事实以及空匹配行为。完整卡放不下时明确省略，不换入不相关的便宜卡。
