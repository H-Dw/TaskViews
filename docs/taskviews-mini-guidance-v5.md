# Mini v5：最小阶段上下文与文件转移配对实验

2026-10-27。本次保留执行器、原生动作编译、journal、来源校验、审计、原 v3 的整轮历史裁剪及 3000 UTF-8 bytes 上限。没有新增规划模型调用，没有按任务答案撰写指导。新配置身份为 `capability_guidance_v5` / `minimal_stage_guidance_v5`；旧配置不能无声恢复为新策略。

## 模型上下文路径

当前观察与未知检查状态 → 最近一次真实执行及真实错误 → 一张当前阶段完整操作卡 → 一条有来源的简短阅读报告 → 必要的未确认效果/循环条件。临近结束再显示终态格式。余下空间不自动填充泛用目录、重复意图或普通历史；查阅入口仍可显式调用，缺能力时仍显示缺口。

最新执行、关键错误不能完整放入时整包省略。操作卡保持参数、适用条件、依赖、后续检查完整；不以列表前缀代替流程。阅读声明不在数值中间截断。来源长 URL、完整哈希、评分、全部候选与检测细节留在本地，模型侧保留可解析的短引用。`fixed_reference` 仍可用于固定成本的离线消融，默认 `refill` 使用当前阶段的真实格式成本；flat/linked 的离线同输入关系消融规则不变。

## 可读性和阶段

1. 原始阅读目标只启用能力，不要求达到某个百分比。有新鲜观察来源的“已经可读”公开报告可优先读；报告仍未验证。
2. 相对 zoom in/out 提供一次可见命令或已冻结应用的精确绑定。应用名被启用不等于窗口/焦点已确认。相对卡不附带 Ctrl+A 和 Enter。
3. 只有准确比例/数值请求才选择数值框完整卡：选中、输入、确认、检查；Ctrl+A 与 Return 保持依赖。
4. 已输入后仅送确认卡，已经 Enter 后仅送效果检查卡。新截图、点击或成功回执不清空未确认状态；显式作用域变化、失效期限和有来源的后续公开报告按原边界处理。
5. 无公开文字的工具决策可以延续最近两轮内、同任务且有观察来源的明确缩放框意图。中间的内容修改、窗口切换等会阻断借用。纯数字、丢失 decision_id、别的任务和失败回执都不建立缩放输入状态。该状态仍标明焦点/效果未确认。
6. 捕捉两轮“相同位置聚焦→有来源的数值缩放输入→滚动”的混合模式，即使输入数值不同。它只提示检查未满足条件，不宣称操作失败；普通输入、单纯翻页和剪贴板不属于该检测。

## Attempts 的核查及调整

核查使用实际完成的 `api_request`，没有将 prepared 当作 delivered：

| 历史条件 | 请求帧 | 有 Attempts 的帧 | 仅一条动作的帧 |
|---|---:|---:|---:|
| 最新 v4 每轮完整/发票 | 40 | 39 | 38 |
| 最新 v4 阶段化/发票 | 29 | 28 | 23 |
| 原 v3/发票 | 22 | 20 | 20 |
| 原 v7/发票 | 35 | 34 | 11 |

Attempts 已接入。它记录实际工具参数、前后观察、后续观察及未知效果，既不判断目标窗口，也不是自动搜索“曾经成功动作”的规划器。v3 同样通常只有一条，不能将后续变慢全部归咎于数量。

新路径保留最近执行事实，并在同一 issuing decision 有简短公开文字时附上带来源的 proposal；没有文字则不编造“打开了哪个窗口”。循环状态关联涉及的执行编号，待确认状态跨截图保留。阅读记忆仍只保留公开结论及原始观察，不能拿隐藏 reasoning 补齐。完整 journal 与索引留本地，不把全部尝试历史重新塞回模型。

## 复核时机

新能力指导路径只接受 `review_timing=stage`，CLI 的 `always` 选项及该展示分支已经删除。`review_prompt=full` 表示终态格式的完整措辞，不表示每轮展示。新默认 `review_budget=refill`，可独立选择固定参考成本；没有合并成含义模糊的压缩开关。

公开保存/导出意图、最近实际派发的完整保存/导出按键、明确结束意图和剩余预算进入原有结束阶段均可触发终态格式。突然请求成功结束而尚无格式时仍由原来的严格校验阻断，并在已有的两次再生成预算内提供完整格式和当前观察编号；没有增加调用额度或替模型填写证据。失败/部分按键不能证明保存成功，也不构成该“实际派发”触发。

历史冻结副本和旧打包器用于复现原版本，不改写旧计划、旧成绩或旧 checkpoint。

## 两格发票实验

根目录：`runs/verified-mini-clipboard-flow-invoice-low40-20261027-v1`。A/B 均采用经核对的原 Mini v3 核心 `4dd4f2b`（`mini_keyboard_memory_v3`），与原发票使用的 v3 核心一致。A 保留明确的选择源文件、剪切、进入目标目录、粘贴连接说明；B 将这一处说明改为独立 clipboard 参考。两格的 Ctrl+X/V 参数、顺序、选择器、历史策略、执行与复核协议完全相同。完整变更证据在 `manipulation.json`。

这是对“流程连接说明”的最小因子检验，不是重现 v7 全部的 clipboard 改动。刻意不同时改变 Ctrl+C 候选、主题路由、history 或复核，否则两格无法分清作用来源。scope 字符长度的差异可能影响临界打包，须以实际请求核查暴露与遗漏。无差异不能排除选择偏置，有差异也只能作为单次配对证据，不能直接认定关键原因。

发票/low 两格依次各一次，40 决策；沿用用户取消联网预检的要求，保留本地离线和资源检查。不会增加第三格或按分数重跑。两个冻结执行副本与本次主工作区优化隔离，每小时有界巡检；正常 0 分继续，异常保存证据后停止。前后核对主工作区 HEAD/分支/index，不覆盖本次授权的新改动。
