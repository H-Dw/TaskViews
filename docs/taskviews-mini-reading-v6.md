# Mini reading v6：先利用已有阅读证据，再决定是否重读

本次优化仅改当前能力指导路径，身份为 `capability_guidance_v6` / `minimal_reading_guidance_v6`。原 v3、v7 冻结副本、旧选择器和旧打包器保持原样；不修改已冻结计划或已完成成绩。没有新增规划模型、GUI 操作或真实 API 调用。

## 为什么“View 已激活”仍会反复读

Current、Attempts、Lessons 原本已经接入原始 journal 和模型请求。此前最小路径通常只保留最近一次执行、一条阅读结论；Lessons 常仅包含未知检查状态。坐标动作没有简短公开意图时，也无法告诉模型“之前试图打开什么”。这不等于模块未启动，而是可复用信息不足。

另一个独立问题是选择规则：模型自行提出的 100% 会被当成新的准确比例需求；菜单、选择百分比、最大化又是不同合法动作，旧的参数重复检测看不出它们服务于同一公开阅读目标。仅再加一句“确认焦点”不能指出缺少的是效果检查。

历史 clipboard 轨迹中，模型第一次决定回读时，相关早期公开报告仍在原生历史中。因此不能把全部反复读取解释为历史被裁；模型还可能在已有信息面前选择重新确认。本改动提供明确的复用条件和操作阶段，不宣称能强制控制模型内部推理。

## 实际执行路径

`task_keyboard_policy(mode='task_capabilities')` 冻结新版本 → `MiniTaskViewsContext.context` 读取最近 96 条原始事件 → `operation_support.build` 建立有来源的状态 → `keyboard_guidance.route` 选择一张完整卡 → `guidance_delivery.materialize` 在 3000 UTF-8 bytes 内装包 → 原注入入口送入本轮请求。

新建入口的 `--keyboard-mode task_capabilities` 使用这条路径。`task_names`、`manual` 或没有 `mini_guidance` 的历史计划继续原路径；仅看 `legacy` / `flat` 名称不能证明新策略已启用。旧策略不能在恢复时被静默替换，必须新建冻结计划。

| View | 本次保留和利用的信息 |
|---|---|
| Current | 当前原始观察、检查状态、待确认效果；阅读进度只引用本轮 Lessons 已装入的报告 |
| Attempts | 最近真实执行及前后观察；从同一 issuing decision 提取完整短意图句。公开表示“再次打开／返回”时，可在有界日志中补取一条词面匹配的导航尝试 |
| Lessons | 真实错误和未验证模型报告；阅读报告保留原句、观察来源、有效期；不重复塞入泛化意图 |
| Keyboard | 一张当前阶段完整操作卡；准确参数、依赖和检查方式保持完整 |

导航召回只表示公开文字匹配，不证明同一对象、窗口、焦点或曾成功。必须在当前图像重新定位坐标；没有回访需求、匹配不足、来源缺失、过期、失败回执和任务切换时不补取。词面召回目前以拉丁字母词项为主，不能声称覆盖中文窗口标题或语义同义词。

## 阅读报告与调整链

- 从公开 content 提取整句；带观察性标题的短数值列表可整组保留，不读取隐藏 reasoning，不补造数字或对象名。
- 单句上限 180 字符，同一公开决策的整组上限 360 字符；不在数字或列表行中间切断。不同观察来源优先，各源轮流，最多 4 组。这是来源多样性，不是自动识别不同文档。
- 保留 12 次决策的有效期，仍受 96 条事件读取边界约束。编辑、撤销、剪切/粘贴等可能改变内容，任务切换和公开纠正使旧报告失效。截图、滚动、缩放本身不证明内容结论错误，也不证明窗口已确认。
- 阅读报告只存一次，放在 Lessons；Current 的引用只在该报告实际装入时一起增加，避免悬空“已有结论”。超过预算的整组保留在本地审计及遗漏计数中。
- 原始任务未要求准确比例时，模型自行提出的数值缩放先转为可读性判断；已输入仍走确认卡，已确认仍走效果检查卡。准确比例任务和图像编辑不被这条阅读规则覆盖。
- 新检测识别不同公开决策下的视图调整链，包括有来源的缩放菜单后“选择 100%”这种省略 zoom 的后续表达。不要求截图相同或参数相同；提示检查可读性，不认定操作失败。导航、编辑、失败派发、新阅读报告和过期会清空链。

本轮上下文明确提醒：先看 Current 的待确认效果、Attempts 的已派发动作和 Lessons 的已读报告；对同一未改变内容，仅重读缺失、冲突或过期的信息。公开结论保持简短并带对象，不要求每轮输出额外标签或长篇推理。终态严格来源校验、原 v3 整轮历史裁剪、工具 ID 配对和官方动作编译均保留。

## 优先级与送达审计

当前原始观察／必要协议 → 最近真实动作／真实错误 → 按键释放条件 → 完整操作卡 → 一组阅读报告 → 未确认效果／调整链 → 其余来源多样的报告 → 必要的历史导航尝试。预算不足时不截断卡或关键执行证据，不自动增加上下文额度。

`mini_operation_support_prepared` 是准备结果；`mini_operation_support_delivered` 才是实际请求注入回执。新增各 View 的入包条数、阅读来源、阅读组数、导航召回的准备／入包状态和明确 `delivered` 字段。`model_adoption` 仍为 `unknown`：请求收到内容不等于已证明模型采用它，参数相同也不作采纳证明。

## 验证口径

产物位于 `outputs/mini-reading-v6-20261027`。定向测试覆盖：不同调整命令、无来源／失败／换任务／过期／真实阅读后的失效、准确比例和已输入优先级、数值列表整组、来源多样性、导航召回的误匹配边界、legacy/flat 实际模拟请求送达、跨版本恢复拒绝，以及极小预算和 flat/linked 同输入一致性。原回归还覆盖旧 legacy 请求等价和严格终态门控。

另对 workflow 26 轮、clipboard 32 轮、v3exact 22 轮共 80 个历史日志前缀调用当前上下文代码。每个前缀分别离线投影三种模式，用固定 3000 bytes 补充预算；禁止网络，没有重放 GUI 或重新评分。此诊断不给模型原有长历史，因此不等同于完整原生请求预算回放，更不是新版本在线成功率或 tokens 收益。数据库前后哈希一致，历史来源保留。

后续若做正式验证，应使用新冻结计划，比较额外阅读/调整次数、首次已读报告后的无新证据重读、有效指导和报告的实际送达、输出／推理 tokens、官方成绩。不能以强行跳过缺失信息的复查或取消终态校验换取更少决策，也不能保证恢复单次 22 决策。

最终结果：21 项新增定向测试和 481 项原相关回归全部通过，Ruff 和差异检查通过；`validation.json` 保存源码与证据哈希，原冻结来源核对全部一致。80 个历史前缀 × 三模式共 240 个投影均有完整操作卡、均不超过 3000 bytes；三份日志中合计 38 个有可保留阅读报告的前缀，在各模式都至少装入一组。legacy 有 30 个前缀装入多组，flat 为 24 个；这也表明结构成本仍会影响能携带的报告数量。workflow 轨迹识别 4 个调整链选卡节点。所有指标是离线入包结果，实际模型采纳和在线收益未测。
