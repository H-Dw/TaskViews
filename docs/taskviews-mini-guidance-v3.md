# Mini 指导与执行衔接 v3

本版本落实五项改进：适用方案的完整组打包、动作前置条件反馈、通用收尾、公开阅读进度和独立复核提示压缩。它不新增规划模型、图检索、路径规划或 GUI 动作，不改官方编译器、评分器与成功标准。

## 冻结与兼容

新计划显式选择 `--keyboard-mode task_capabilities`，冻结 `capability_guidance_v3`、`complete_guidance_and_feedback_v3`、`public_operation_semantics_v3`、目录/库哈希、决策上限和 `--mini-review-prompt full|compact`。默认 full。compact 仅在 task_capabilities 下合法。运行和恢复必须使用同一冻结策略，不能在 checkpoint 上切换提示模式或预算。

未启用新指导的 legacy 路径保留原打包和选择行为；本轮“当前 legacy”则是旧四 View 外形加新指导策略，不能当作原 v3 整体重跑。flat 使用共享实体及 View 引用，关闭新增关系；linked 的离线一致性仍验证，本轮不在线评测它。

## 完整指导与具体反馈

按公开任务冻结通用能力及辅助目录；区分动作意图和界面描述，覆盖阅读、比对、图像编辑、拖动、文件操作等表达。启用目录不证明当前软件、窗口、焦点或选择正确。目录没有请求的具体绑定时记录缺口，不回传相反方向作为替代。

每个工作流显式列出依赖；复制/剪切、放大/缩小是替代方案，不拼成顺序操作。选定流程整组接纳或整组省略，不截断配方字段和列表前缀。相同相关性使用稳定身份排序，目录重排不改结果。旧目录中的绑定也可通过新选择器进入此规则；没有人为把 Ctrl+V 永久置顶。

关键执行证据和严格复核协议优先，然后送达当前有效反馈和完整操作卡，再考虑阅读进度、目录及普通历史。保持 3000 UTF-8 bytes，长来源、候选分数和完整哈希只放本地审计。空间不足明确记录整组省略，不把目录可见算作完整指导送达。

新增反馈由已执行日志和公开意图确定：拖动的坐标是终点，需要先依据观察定位起点；缩放输入后核对确认及实际显示；成对释放按住的键；识别长度 1–3 的重复命令模式。重复模式不依赖截图完全相等，改变拖动时长不算解决起点条件。正常滚动、输入、剪贴板不以重复判失败。反馈保留事件来源，拖动/缩放/循环反馈限最近两次决策；工具回执不升级为业务成功。

## 阅读与收尾

仅从已有公开 content 抽取短而完整的判断，最多两条，每条最多 180 字符；不读取隐藏推理，不裁断长数字或句子。记录原决策及观察引用，身份为 `model_reading_proposal`、verification=unknown，12 次决策后到期；编辑、撤销、公开更正、任务切换使旧记录失效。视口变化不使旧坐标继续有效；矛盾或不清楚的值需要新观察。它不是文档语义识别或事实认证，长段落不保存时有审计原因。

冻结的剩余决策数在当前状态可见。接近上限或已有公开保存/导出意图时，提示完成待处理对话框、释放按键并核对公开目标。仅在用户目标需要时保存/导出；不植入 benchmark 文件名、评分后处理或答案，不自动补动作或宣布成功。

## 完整与压缩提示的独立对照

full 保留完整复核说明，compact 使用较短但包含相同字段、来源和大小约束的说明。两者共用同一严格解析、来源验证、unknown 等级、终态拒绝条件、最多两次再生成以及时间/token 预算。不把字符串引用转换成整数。

同一日志输入下，两种模式均按完整提示成本选取事实，compact 腾出的空间不补历史或指导。全量协议始终用于纠错反馈；这轮比较的是正常轮次的提示呈现，不能解释为取消检查。不同在线轨迹仍会造成不同事实，不能声称每一步相同。

## 评估

发票/GIMP × 当前 legacy/flat × full/compact，共 8 格，全部 low、串行、每格一次。采用同一冻结新指导库及代码；比较上一轮原 v3 keyboard 或新指导 v2 属于版本组合比较，只有本轮 full/compact 是预先指定的提示消融。
