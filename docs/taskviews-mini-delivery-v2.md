# Mini 有效信息送达 v2：实现、溯源与 Graph 下一步

2026-10-24。用户明确要求的评测结束后优化；不是对已完成 r007 评测的自动修复或结果替换。保留旧实验、冻结计划与 7/10 自动修复账本。本次不启动在线任务、不调用模型、不修改官方动作编译器或评分。

## 实现与使用

新增可选 `evidence_first_delivery_v2`。旧 `legacy` 与 Graph v1 继续保留，缺少新配置不会自动升级。新旧打包策略写入冻结 `mini_graph`，运行环境从冻结计划设置，checkpoint 禁止跨策略恢复。v2 仅适用于 `flat`、`linked`，两者仍在相同输入上按 linked 完整成本选择同一组事实；flat 删除 links 后不补记录。

在 `scripts/verified_invoice.py prepare` 或 `scripts/osworld_native_experiment.py` 的现有准备参数中添加：

```text
--mini-graph-mode linked --mini-graph-packing evidence_first_delivery_v2
```

flat 消融使用同一 packing，将 mode 改成 flat。原始对照省略 packing，legacy 使用 `--mini-graph-mode legacy`。验证入口 `scripts/validate_verified_invoice.py` 和定位诊断入口也接受 packing。必须新建计划和资格证明；本次不改写、启动任何旧计划。`verified_mini_graph_matrix.py` 的已完成旧 campaign 不自动切换到 v2。

实现位于 `kobe_views/mini_delivery.py`，入口由 `mini_graph.py` 分流：

1. **无损减少结构开销。** 事件编号由 `eN` 还原；来源表保留事件类型和完整 256 位哈希（base64 编码，不截短）。单一 facet 的名字已在 View 引用中出现，节点只存 fact；多 facet 原样保留。相同的 unknown 检查状态显式引用 current，不重复四遍键名。相同关系/目标的 links 合并来源列表。解码后节点、所有关系、来源哈希、等级与原有事实一致。
2. **按完整配方装包。** 保留完整 topic 优先；容不下时在当前 topic 内按目录顺序保留完整 recipe，显示 `recipes_omitted`。每条配方的动作参数、意图、范围、核验提示、来源保留，字符串和错误信息不截断。历史按键 memory 仍整条装入/省略，不把修正建议变成已执行操作。
3. **恢复查询入口。** 已启用软件主题和常见 general 主题构成紧凑菜单；`<key_lookup>general</key_lookup>` 或已启用的软件目录名可请求该目录的主题。精确 topic 请求仍用原选择器。菜单在可选旧历史/意图之前装包；配方不能容纳时也尝试菜单。不会把启用目录当作当前焦点，不启用未冻结的软件目录，不采用旧意图填充空的新意图。
4. **关键证据优先级保留。** 当前观察、unknown 状态、完整复核协议、最近动作、错误/已有复核优先；接着是配方/查询入口、重复操作提示和其他历史。必要内容超预算仍整包省略，不切换为 legacy。极长错误等情况不保证所有可选信息都送达，审计保留省略信息。
5. **可核对实际送达。** 新增候选 topic、配方数、配方省略数和目录送达标记；Graph 审计关系数使用解码后的真实边数，不把压缩组数当边数。实际投递仍以原 delivery receipt 为准。

v2 没有扩大最近 4 条操作等候选窗口，也没有实现全图语义检索或规划。部分 topic 只能保留一条完整配方；目录排序未必是当前意图的最优配方次序，这是后续可独立验证的限制。

## 离线证据

`scripts/compare_mini_delivery.py` 通过只读 SQLite 连接和带 seq 上界的临时视图，重建已完成 r007 的 18 条轨迹、510 个决策边界；所有选择器和引用读取都只能看到该边界以前的事件。官方结果、截图及原日志不改写，不读取 gold，也不重放模型响应或 GUI。

每个边界分别执行 v1、v2 的完整候选选择和 linked 成本打包，并验证各自 flat/linked 除 mode、links 外完全一致。补充上下文预算统一为 3000 字节；这不是对不同在线轨迹的因果消融，也不声称重现每个原请求的原生历史剩余空间。

| 同一批 510 个日志边界 | Graph v1 | delivery v2 |
|---|---:|---:|
| 已有按键候选 | 106 | 106 |
| 送达含配方的包 | 0 | 106 |
| 送达完整配方条数 | 0 | 116 |
| 送达查询目录的包 | 0 | 404 |
| 最近动作缺失的快照 | 17 | 0 |
| 保留完整复核协议 | 510 | 510 |
| attempts 记录数 | 487 | 492 |
| 总 packet 字节 | 1,460,609 | 1,448,041 |
| 最大 packet 字节 | 2,996 | 3,000 |

其中 18 个首轮快照没有历史动作；“最近动作缺失”仅指已有最近动作却没有送达。v2 共省略 135 条整配方，明确计数，不能说全部目录已送达。116 条配方来自固定日志中的原有选题，未声称新产生的软件专属 lookup 已在真实模型上验证。

原在线 flat/linked 的 345 轮中已有 75 个按键候选被全部挤掉；上述 510 快照还包含 legacy 轨迹的 31 个候选，因此总数为 106。旧策略与新策略都在所有轨迹上重建为 Graph，不将重建结果冒充新 benchmark 成绩。

输出：`outputs/mini-delivery-v2-20261024/comparison-final.json`，逐轮保存字节、配方/目录、动作、复核和边数，绑定原计划 SHA256。测试覆盖无损编解码、跨 View 多 facet、UTF-8 预算、严格消融、旧 legacy 请求基准、目录隔离、冻结策略与恢复拒绝；真实 actor 集成使用离线传输，验证没有新增请求。

验证结果：439 项回归通过，Ruff 通过；flat/linked 各自的轮次上限、显式结束、空动作，共 6 个原运行器模拟场景通过。传输与 GUI 均被模拟，输出中的 0.125 是验证哨兵，不是 benchmark 成绩。源码与证明的匹配记录见同目录 `validation.json`。这些验证不等于下一轮正式实验要求的完整资格程序或真实 API 探针。

## 公共提示、按键和复核的变化

首先区分历史版本。用户给出的已完成运行中，发票 high 是 `e5451c8` 的按键优化 v3，GIMP 是 `4dd4f2b` 的 v3，VLC 最好的 Mini 是 `ae27018` 的 v7；未找到精确 `5a839d9` 提交的正式评测。`5a839d9` 的按键目录、选择器、legacy 打包器、artifact 协议与 r007 冻结源码相同。不能把 v3→v7/5a 的变化说成 Graph 改造时才发生，也不能将历史 v3/v7 成绩标成 5a。

| 机制 | 历史按键优化 v3 | v7/5a 与 r007 公共路径 | 可能影响 |
|---|---|---|---|
| 选题 | 在近期意图中找主题；不匹配时默认 editing | 只用最新公开意图；不匹配返回 None | 确定减少持续配方暴露；旧主题可能不适用的风险也下降 |
| 操作主题 | zoom、file_transfer、window 等较宽松匹配 | 通用主题缩窄；软件专属主题需冻结目录与精确 lookup | invoice 不一定显式提及 GNOME Files/Evince，可能失去旧文件转移/缩放路线 |
| 目录发现 | 每个键盘记录携带小型目录 | 扩展目录更大，lookup 被放在最低优先级 | 模型难以发现可用主题；Graph v1 中实际完全消失 |
| 每帧公共提示 | 精确后端按键 token 提醒；无效动作后尝试其他可见/键盘路线；提醒图像变化不等于成功 | 保留坐标、焦点、可见效果核验，增加产物复核要求；部分旧按键/替代路线文字不再每帧出现 | 注意力从操作路线转向产物检查的假设合理，但需对照实验才能认定 |
| 复核协议 | 没有现在的严格终止前 artifact_review gate | 完整 schema 每轮占预算；成功终止前必须给出四项来源绑定报告，content_previewed 引用当前观察；unknown 不升级 | 确定增加上下文与结束条件负担；可能导致更多检查与推理 |
| 纠错反馈 | 旧共享原生修复路径 | Mini 报告修复；r007 增强字段/当前观察说明，引用占位符为正整数 | 只在报告被拒后触发；未新增额外角色，仍共享原来的两次再生成和预算 |

坐标模式的 relative 规则没有在本轮变成另一套投影；不能将 absolute 示例文字的删减当成本轮 relative 模型失误的既定原因。

### 哪些解释证据最强

**第一是可用信息被减少及预算竞争。** 历史 v3 发票 high/low 的配方送达分别 26/26、22/22，GIMP 为 28/28；r007 legacy 全部六格共 31/165，flat/linked 为 0/345。旧文件转移 scope 直接解释选源、剪切、导航到目标、粘贴；新一般剪贴板配方不一定包含这条工作流程。以上可以从实际请求和代码核对。

**第二是复核协议和公共提示改变任务负担。** 这是 v3 到后续版本的共同变化，可以影响 legacy；但 invoice/legacy/high 的 40 次调用没有报告拒绝或再生成，因此不能将其 0 分归因于“纠错重试把次数花完”。更可能的候选解释是过程选择/信息供给变化，仍需逐轨迹行为核查和同版本提示消融。

**第三是模型轨迹差异。** 每格只跑一次；任务特定失败不能等同稳定的总体退化。legacy 也并非三个任务都远差于旧 Mini：high 发票 26 决策/1 分→40/0，GIMP 28/1→19/1，VLC v7 9/1→10/1，且 VLC 输出 6,807→5,550。VLC v7 原本也只有 1/9 轮拿到配方，是“所有成本恶化均因按键丢失”的反例。

建议后续分开检验：固定同一 actor/review/budget，只切换 v1/v2 打包；再单独比较选题策略/提示措辞；若评估复核负担，保留明确的独立协议消融，不能以提高得分为由静默放宽严格引用或终止判据。

## linked 是否需要完整图检索或路径规划

**应该补可度量的图检索，但现在不适合直接上完整路径规划。** 现有 links 有来源追溯、证据闭包、共用实体和精确参数匹配的用途，未证明其能指导下一动作。当前大多数边只是 in_task、before/after、issued_by；它们描述“发生了什么、来源在哪里”，没有“哪个操作会解决当前任务”的效果模型。Graph v1 实际 matches_recipe 为零，模型得到的主要是结构标签与额外阅读负担。

建议下一阶段独立版本化以下检索过程：

1. 以当前观察、最新实际动作、明确错误、当前精确按键 topic 为锚点。仅使用当前 episode、原始 instruction 和已冻结目录；不将模型 proposal 当事实种子。
2. 在有证据的关系上展开最多 1–2 跳，取对应 decision、前后观察、明确错误、匹配配方；保留原始重复动作的独立身份和顺序。图遍历只是候选检索，不是成功/因果推断。
3. 按“当前未解决问题的直接证据→相关失败/重复→配方及其局部执行证据→较早意图”排序，按整组证据的实际序列化成本选择。不要把整个子图倾倒给模型；只交付能回答当前问题的小组事实与可追溯引用。
4. 当扩展范围超过当前 last-4/last-32 等窗口时，冻结为新的 retrieval policy，记录扩展数、命中数、过期/跨任务排除和实际送达，不和现有 v2 当作相同候选集合。
5. 检索消融与显示 links 消融分离：v2 flat、v2 linked 先共享相同候选；随后新增“同一图检索后的 flat/linked”成对条件。否则同时换检索和展示，无法判断收益来自哪部分。

完整规划还缺少可复用的状态定义（软件/窗口/焦点/模态对话框/文件状态）、操作前置条件、经观察支持的效果、状态等价判据、时效与不确定性。对“观察→动作→观察”的日志直接做最短路径，只得到历史执行链，不能得到可靠的未来操作方案。相同快捷键在不同焦点下效果不同，旧坐标也可能过期。

应先验证检索能减少重复无效操作、恢复相关记忆、降低同分任务的决策/输入输出 tokens，再考虑有限深度规划。新增规划须单独冻结调用与 token 成本，不能把规划额外调用藏在原来的 40 次 actor.predict 之外。本次只实现送达层，不宣称实现了这些检索或规划能力。
