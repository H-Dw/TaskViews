# 改进方案逐项来源与缺陷归属核对

以下均为建议，尚未实施。原生实现、官方配置与项目适配分别标注；不把 K3 native function calls 称为原 QwenAgent XML 路径。完整原因与原流回放见 [分析报告](report.md)。

|项|建议|是否 OSWorld 原生|对应问题|缺陷/限制归属|实施边界|
|---|---|---|---|---|---|
|1|继续原截图处理、固定 absolute/1920×1080 和官方 project_point|直接复用官方实现 + 官方支持的配置|消除截图尺寸与坐标单位契约分歧；当前 v6 尚无坐标执行证据|旧自定义 relative 契约与模型像素输出不匹配；官方支持两种单位并非缺陷|当前契约保持；不能据输出临时猜单位、夹取或换缩放。|
|2|继续原 translate_tool_calls、controller、runner、reset、evaluate|直接复用官方代码，当前已经如此|保证完整候选整批校验、逐条执行和真实评分|本轮未到 env.step，没有证据证明这些原实现失效|无需重写或回退执行底座；native 协议同样可以调用这些实现。|
|3|XML Completion 空字段采用官方 _text / 字符串聚合语义|复用官方已有兼容机制；修自定义桥接边界|三个完整 SSE 被聚合为 content=None 后遭强制 str 拒绝|明确是自定义 SSEAccumulator 与 K3XMLClient 契约不一致|最高优先级；保存原流/原对象，对官方 Completion 做规范化，不伪造动作。|
|4|把 K3 native function calls 作为预选共同协议，沿用官方 schema/编译/执行|供应商必要的自定义协议适配；不是原 QwenAgent XML predict 的逐字复用|真实任务中 K3 对文本 XML 声明只有叙述，旧 native 请求已有实际 tool_calls|跨模型协议不匹配与当前迁移判断不足；不能简单认定 OSWorld 执行器有 bug 或 K3 完全不支持 XML|推荐下一步验证；两臂共用同一适配器，与 XML 单独比较，不自动回退。|
|5|分拆合成 XML、真实任务动作、字段、历史/修复/摘要兼容准入|项目自定义验证；可利用官方 smoke 入口，新增断言不是官方评测规则|两合成回合被笼统用作真实任务协议兼容证据，没有覆盖空正文与实际回执|项目迁移验证覆盖不足；官方框架不负责证明额外 K3 适配器正确|先短程验证完整动作→原 env.step→回执→后截图；兼容测试不当正式成绩。|
|6|可选：对纯执行叙述但无工具调用做有限协议修复|额外自定义增强；不是固定官方 parser 的行为|完全无 XML 返回 []，不触发原两次修复，进入 ASK_USER 循环|官方允许无动作交互的设计在通用供应商迁移时有适用限制；不等于原 parser 错把合法 XML 丢弃|仅新命名策略两臂共用，保留原预算/期限和合法 call_user；严格原版对照不能悄悄加入。|
|7|继续显式 terminate / 官方上限结束，公开 terminal judge 的选择|原结束流程 + 官方支持关闭 judge 的配置；不是新自动停止规则|防止 judge 恢复上限自动 DONE 被误当完成；当前关闭后暴露无动作循环|官方默认结束策略的适用限制与此前用户授权配置；不是空正文崩溃起因|不建议靠重新启用自动 DONE 掩盖问题；新增结束规则须独立政策和真实评分说明。|
|8|XML 继续官方历史算法，K3 原始消息身份恢复改为显式记录|官方 history + 必要的自定义供应商历史兼容|避免内容文本别名歧义或原 reasoning/tool IDs 丢失，准确区分历史文本与真实回执|目前未发现无动作由历史丢失造成；别名缓存属于自定义结构性风险，非已证实运行失败|不改变原历史语义来假造反馈；native 历史保留真实 assistant/tool ID，承认与 XML 历史有差异。|
|9|按用途区分 actor、官方摘要与 TaskViews 分析；显式各角色参数/预算|原官方摘要调用逻辑 + 自定义 K3 参数和预算适配|summary cap4096/原 enable_thinking=False 被供应商统一 max 取代；错误标成 executor；分析 cap4000 有 length/期限失败|Qwen 与 K3 参数不等价、当前角色映射/文档和分析预算适配不足；不是官方摘要源码未运行|actor max/16000 保持；辅助角色在供应商确实支持的范围内声明策略，不能假称关闭 thinking。|
|10|保持已授权整步/资源保护，说明其与原客户端的区别|用户授权的共同自定义运行政策，非 OSWorld 默认|保障总时间、输出和实测 owned 内存预算；避免截断动作被执行|本轮无资源阈值或网络重试导致无 XML；修改保护没有针对该原因|保持限制并披露，不放宽资源、不把完整空响应当截断。|
|11|修 telemetry.emit 的 kind 参数冲突并回归 SQLite→事件输出|项目自定义被动记录代码修复|SQLite 写入后 emit(kind positional, kind keyword) 抛 TypeError，导致513记录告警|明确自定义 telemetry 缺陷；异常捕获，非本轮 actor/控制器失败|最高优先级基础修复；记录不能改变动作、反馈或停止策略。|
|12|共同 UI-KOBE 转换图底座，TaskViews 只扩任务模块与证据上下文|项目自定义功能；OSWorld 没有原生 TaskViews/该任务图机制|将任务信息跨页面管理，依据真实 source/target/action/receipt/观察形成证据|属于实验组功能需求与当前设计完善；不能当作官方执行器替代|两臂共同被动记录；TaskViews 只加读取/存储/分发及辅助推理，不修改 actor 目标、坐标或终止。|
|13|基于 frame、日志 seq、图 revision 和需求变化缓存 TaskViews，区分模型提议与观察事实|自定义信息管理优化|同截图重复分析消耗时间；memory delta/模块 verified 容易被误当 GUI 进展|TaskViews 调度/证据管理范围的不足；不是 OSWorld 坐标或执行缺陷|优先消费已落盘事件；观察事实、推断、模型验证标签分别存储，过期/不同目标需求时再生成。|
|14|真实 SSE 兼容回归 + 更新 README 的摘要、在线评测和原生范围描述|自定义测试与文档维护|已有成功 XML mock 未捕获本次跨层 None 冲突；文档声称没有摘要/尚无在线实验|项目测试覆盖与文档不足|加入三个真实流及 prose/call_user/length/summary/history/记录链路用例，不用“官方源码未改”替代接口验证。|

确认是当前自定义代码缺陷的有空字段处理、emit 命名冲突、用途标记，以及迁移验证/文档覆盖。官方的 XML 提示和宽容空动作语义具有模型与政策适用边界；没有证据表明本轮的官方截图、坐标投影、执行器或评分器出现故障。执行协议选型与 TaskViews 图服务需要自定义，不能宣称全部替换成 OSWorld 原生代码。
