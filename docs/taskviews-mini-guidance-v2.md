# TaskViews Mini：检索语义、阶段操作卡与 v3 历史策略

2026-10-26。修改仅在当前主工作区完成；未修改冻结实验副本、官方动作编译器或评分器，未运行新模型请求或 GUI 评测。没有增加 linked 图检索或规划。

## 历史裁剪的核对结果

原 v3 运行提交 `0a5b6f2a8824008dc3bba01803b1b43369016627` 的 `native_history.compact` 与修改前当前实现相同。因此本次没有把一种新算法冒称为恢复 v3，而是将原策略明确命名为 `native_v3_whole_turns_v1`，随每次 `history_trim` 记录实际配置，并保存原实现为回归基准。

原策略继续按历史轮数、截图折叠、真实文本／序列化大小限制裁剪最旧的完整轮。保留原任务、当前图像、assistant/tool ID 配对及保留轮内的原始 reasoning；不会单独删推理或生成摘要。历史实验均为 history=20、image=1、fold=1、text=32000 chars、reserve=10000 chars、rough=12000 tokens。策略不会覆盖其他调用者已声明的参数。

原函数保存在 `tests/fixtures/native_history_v3.py`，25 个合成输入对照覆盖不同轮数、推理长度、中文当前观察、预算和超限拒绝；比较结果、完整请求组成及原始工具 ID，而非只检查策略名称。旧 legacy 请求基准继续验证。

## 新冻结配置

新建 `--keyboard-mode task_capabilities` 计划采用：

- `capability_guidance_v2`
- `public_operation_semantics_v2`
- `compact_stage_card_v2`
- `journal_seq_local_audit_v1`

原始公开 instruction/related_apps、指南库哈希、能力、启用目录、语义／打包版本仍被冻结。旧计划不自动更新；v1 指南计划不能在新库上恢复，需用原冻结代码继续，或重新准备明确的新实验。没有指南字段的旧路径仍使用原选择器和打包器。当前改动不能直接热加载到已有实验。

文件转移支持 copy/move/transfer 及“put/place/organize files into a folder”等对象—目标位置关系，不依赖任务编号、文件名、行业对象、预期答案或评分规则。阅读包含 read/review/compare；缩放包括 zoom in/out、设置缩放值、缩放字段的输入—提交。水平滚动、最大化和菜单操作也有独立语义。

复制／移动冻结必要的粘贴能力；阅读冻结滚动、缩放、最大化、窗口切换能力。文件操作、截图、导出、阅读同时启用文件管理器辅助目录。明确的 PDF 阅读可将 Linux Evince 目录列为条件性参考候选，绝不表示它已安装、正在前台或拥有焦点。其他软件仍由原名称规则和手动选择决定。

动作提议与状态描述分开。例如 cut off 不等于剪切，menu is open 不等于打开文档，open a context menu 不触发 Ctrl+O，Zoom In is disabled 不表示应该放大。已执行动作才推进剪贴板流程；公开状态始终是未验证提议。

运行时明确的文件意图独立于原任务分类。若必要目录未冻结，则保留 `directory_not_frozen` 缺口并提供条件性无快捷键检查卡；不自动启用目录。新能力、未知 lookup、没有启用的精确配方分别留审计原因；模型侧 `guidance_status` 显示缺口。普通安全指导可以使用已启用的 general，不把它冒充缺失的软件专属配方。

## 当前阶段的一张完整卡

先满足当前观察、完整复核协议、最新动作和关键错误证据，再选择最相关的完整卡，之后才尝试通用目录和普通历史。候选由阶段、明确意图、时效及范围排序，同分按内容稳定 ID 排序。较旧候选的“软件专属”加分不能盖过最新意图。没有使用目录顺序取前 N 条。

卡保留范围、当前图像的焦点确认前提、准确按键参数、必要后续步骤、检查方法，以及互斥选项。文件移动完整包含剪切—进入目标—粘贴—检查；可编辑缩放字段完整包含聚焦—全选字段—输入目标值—Enter—检查比例及可见范围。未确认字段可编辑时使用可见缩放控件；不猜测坐标或数值。

指南 URL、完整来源／记录哈希、候选分数及语义命中原因留在本地 `mini_guidance_prepared` 审计；模型侧只保留短 `source_ref` 和 episode 内 journal seq。`event_sources` 和原 SQLite journal 保留完整身份／哈希映射，graph 审计也继续保存完整索引。序列化前的来源／端点校验不变；短引用展开不会伪造哈希。无指南的旧 codec 不变。

每轮 packet 独立可读，仍最多 3000 UTF-8 bytes。最高优先级卡装不下时标记 `omitted_budget`，不拆掉尾部检查、不偷偷换成便宜但无关的卡。最小必需状态也装不下则整包省略。flat/linked 按 linked 完整成本接纳相同事实，再删除 flat 的关系；不回填空余字节。

本地审计仍区分包送达、目录可见、所需配方送达、完整工作流、过时／不适用情况。所需指导来自确定性路由估计，没有独立标注时不声称语义准确率。参数相同、卡在请求中都不证明模型采用了建议。

## 反复操作的来源与此次处理

“阅读阶段”指打开源文档、切换／调整窗口、缩放、滚动、读取并比对可见信息；它是实际 GUI 轨迹，不是内部推理计时。文件整理、移动和最终检查属于后续阶段。阶段划分也不表示评分器已经确认读数正确。

历史 v3＋新 keyboard 的前段反复点击／三击缩放字段并输入不同数值，后来又重新打开和读取文档；旧路由缺少 zoom in，常送达 document.open/text.edit 或 focus.verify，字段提交没有作为完整依赖一起提供。cut off 又被误当作剪切。原任务能力漏识别进一步使后续明确的 move 意图无配方。输入新缩放值并不等于缩放已经提交、更不等于看清内容。

历史 v7 的第 8–17 步包括同位置点击、双击和 Super 交替，随后连续按 Super。坐标仍合法，工具正常返回，不能因此证明点中了预期文件。旧连续重复规则不能识别早期交替循环。v7 第 16、17、18 步确实收到 recent_repetition，repeat_count 为 2、3、4，same_image_count 为 2、2、3；第 18 步才改用文件管理器。不能把这段问题全部归因于提示未送达。

读取实际 API 请求后确认：原 v3、v3＋新 keyboard、v7 各自的 system prompt、静态坐标／复核说明和 View 标签均只有一个版本。变化的是图像与观察编号、公共回复、裁剪后的历史、尝试／意图记录、检索出的指导和重复计数。v3＋新 keyboard 没有复核再生成；v7 的一次复核纠错在第 35 步，发生在循环之后。因此没有证据支持“框架在循环中多次改写 system prompt，但修改都无效”。

提示未形成闭环的原因包括：没有匹配当前操作的完整指导；状态变化只记录次数，无法指出正确目标位置；动作交替或参数改变不满足连续相同判定；工具返回和像素差异无法证明业务成功。长 reasoning 被按原协议带回历史后，又触发整轮裁剪：原 v3 平均保留 10.36 个历史轮，v3＋新 keyboard 只有 4.83 个。裁剪算法相同，实际保留的信息却不同，可能进一步放大重复读取。此项是机制解释，不是单因素因果证明。

本次除检索和完整卡外，还检测最多六个已确认动作中的两次相同短周期（周期 1–3），要求参数及原始前后图像哈希对应一致。确认的循环优先提供重新定位目标、检查焦点或改用可见菜单的卡，不自动重试、不增加模型调用、不改动作编译。剪贴板、文本输入、画面正常推进的滚动不被此规则认定为循环；所有效果仍 unknown。动态图像或语义相似但参数不同的循环仍可能漏检，未宣称通用防循环已完成。

原 v3 那次运行更早选择合适的窗口操作，阅读只用 11 步，v3＋新 keyboard 用 23 步；后续文件阶段分别 11 和 12 步。原 v3 第 2 步最大化时尚未收到 window 指南，所以不能把全部差异归功于其配方。原 v3 后续文件流程的持续完整指导和更充分的历史也是有利因素，但仍是每版本单次轨迹，不能保证重新运行复现 22 步／6095 输出 tokens。

## 验证与边界

同输入验证使用既有 journal 和当前投影重建，不执行保存的 GUI 动作，不重新打分。70 个历史决策快照分别打包为 legacy/flat/linked，检查完整卡、预算、来源和严格 flat/linked 一致性。它衡量模块结构，不是新的 benchmark 成绩，也不是所有当前所需指导都正确的证明。

最终 375 项定向回归、Ruff 与 diff 检查通过；历史 current、v3-keyboard、mini-v7 冻结源码哈希均保持不变。同输入重建使用当前关键事实投影，并不声称与旧请求逐字节相同。

|同输入模式|完整候选卡入包|最大 packet bytes|
|---|---:|---:|
|legacy|70/70|2975|
|flat|70/70|2785|
|linked（仅结构兼容检查）|70/70|3000|

这里的完整候选卡不是人工标注的正确指导。例如词汇规则仍可能漏掉含代词的“create one”，退回原任务候选；本次不把 70/70 当成实际所需指导准确率。实际采用情况也仍未知。

备份、定向回归、原 v3 历史源文件、实际旧请求提示对照及同输入回放在 `outputs/mini-guidance-v2-20261026/`。`before/kobe_views/mini_delivery.py` 来自此前已核验相同的冻结 b8c13ab 快照，其他列入备份的文件在编辑前复制；原工作区 patch/status 一并保存。最终验证摘要见该目录 `validation.json`。

正式验证收益需要在相同任务、模型、reasoning、初始环境和预算下重新冻结独立计划，比较成功率、循环段、准确动作率、决策数及 tokens。此次未启动这类评测，也未恢复暂停的巡检。
